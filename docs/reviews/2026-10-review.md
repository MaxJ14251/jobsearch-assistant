## Findings

Severity: **critical** (a broken promise or data loss in normal use),
**major** (wrong behaviour a person will plausibly hit, or a broken
invariant), **minor** (edge cases, hardening). Nothing was rated critical.

### Major

**R-01. Drafting moves an applied, interview or closed application back to `ready`.**
- **Where:** `jsa/drafting.py:139` records `ready` as the agent whatever the current status.
- **Reproduced:** swipe right, record `applied` then `phone_screen`, and let the Turbo worker draft. The status is now `ready`, set by the agent. The Tailor button does the same at any stage.
- **Knock-on effects:**
  - `outcomes.furthest()` treats it as undone and drops the application from `jsa outcomes`.
  - The apply-by-hand checklist reappears, and its button then refuses.
- **Fix:** record `ready` only from `saved`, `drafting` or `ready`. Otherwise record an event at the same stage, saying what was drafted.

**R-02. The dashboard can return 500 "no such table" whenever anything upgrades the tracker.**
- **Where:** `jsa/db.py:179-184`. `migrate()` drops every view, each drop committing on its own, and recreates them later.
- **Reproduced:** a reader looping on `v_new_matches` during 40 upgrades got 37,287 errors.
- **Who triggers it:** `db.upgrade()` runs on most CLI writes, `jsa daily` and discovery, including setup's background discovery inside the dashboard.
- **Fix:** rebuild a view only when its stored SQL differs from the schema, and do it in one transaction.

**R-03. `inbox.fetch` holds the write lock while reading mail.**
- **Where:** `jsa/inbox.py:389-421`. The first `INSERT OR IGNORE` opens a transaction, and the loop then makes IMAP round-trips before the commit.
- **Reproduced:** a writer started after the first insert got "database is locked".
- **Effect:** dashboard saves and Turbo drafts fail while "Check email" or `jsa daily` runs.
- **Fix:** fetch everything first, then insert and commit.

**R-04. `jsa restore --all` can stop halfway, and the safety copy's path isn't printed.**
- **Where:** `jsa/backup.py` `restore()`. The tracker is overwritten first, then `rmtree(output)` and `copytree` run. `cmd_restore` catches only `BackupError`.
- **Reproduced:** a .docx held open on Windows left `output/` half deleted, the profile not restored, and a traceback.
- **Fix:** build the new `output/` beside the old one and swap them in. Catch `OSError` and name the pre-restore copy.

**R-05. `jsa find` can say "same job" for a different company whose name starts the same way.**
- **Where:** `jsa/find.py:198`. Prefix candidates ("name starts the same") feed `judge()`, which can return `same`.
- **Reproduced:** "Scale AI" matched a stored "Scale Computing" job as the same job.
- **Effect:** the job page checklist then says "Apply on the employer's site instead" with the other company's posting.
- **Fix:** a prefix candidate is at most "possible".

**R-06. `jsa find` treats the same city name in different states as one place.**
- **Where:** `jsa/find.py:244-246`. A bare city match is enough.
- **Reproduced:** "Portland, OR" against "Portland, ME" gives `same`.
- **Fix:** when both sides name a state, the states must match.

**R-07. The checklist's "I applied" is a dead end when an approved resume exists but another was sent.**
- **Where:** the template shows the confirm box only when no resume is approved (`jsa/web.py:1732`), while `do_applied` asks for it whenever the chosen resume isn't approved.
- **Scenario:** choose "None of these (my own)" with v1 approved. The page says "Tick the box", and there is no box.
- **Fix:** always show the box, worded for the case.

**R-08. A failed backup is kept, counted as fresh, and can push a good copy out.**
- **Where:** `jsa/backup.py:85-118` leaves a half-written folder on failure. `listing()`, `prune()` and `newest_age_days()` count it. `daily._backup` prunes even when verification failed.
- **Fix:** remove the folder on failure, skip folders without a manifest, and prune only after a verified copy.

**R-09. A `javascript:` link from a job board becomes clickable on the dashboard.**
- **Where:** `jsa/web.py`: the job page, checklist, Find and Turbo links render the stored board URL. Discovery stores URLs from feeds with no scheme check; only manual entry checks.
- **Reproduced:** a stored `javascript:` URL rendered as an `href`. A click would run on the dashboard's own origin, where it can read the CSRF token.
- **Likelihood:** it needs a hostile or compromised feed, so it is unlikely.
- **Fix:** a `safe_url` filter that keeps only `http(s)`, on every link built from stored data.

**R-10. Resume import can send the person's name to the model.**
- **Where:** `jsa/resume_import.py:61`. The name pattern misses common shapes ("José García", "Jane Doe, MBA", "Jane Doe | Data Analyst", "Ludwig van Beethoven"), and the identity check that follows is built from the same pattern, so it can't catch the miss.
- **Reproduced** with fictional names.
- **Fix:**
  - widen the pattern: Unicode letters, lowercase particles, a trailing credential or headline;
  - also check the prompt against the live profile's identity when one exists.

**R-11. Interview prep tells the model the degree was "NOT conferred" for everyone, and can't run for someone who holds one.**
- **Where:** `jsa/prep.py:243` hard-codes the sentence. For a held degree, `facts.degree_answer` returns the credential, and `assert_no_degree_claim` then refuses the standard drills.
- **Reproduced** with "B.S. in Computer Science" and "PhD, Physics".
- **Effect:** affects new users from the setup page, not the owner.
- **Fix:** build the sentence from `claims_a_degree()`. Run the degree check only on model-written text, and only when no degree is held.

## Checked and found sound

- **CSRF and Host:**
  - Every POST needs the token; other methods return 405.
  - Malformed or huge multipart bodies, repeated or file-part `csrf` values, lying or malformed `Content-Length`, and JSON or text bodies were all refused.
  - Host variants (`localhost.`, `127.1`, `@evil`) were refused. `[::1]` and `LOCALHOST` are accepted, which is harmless.
- **GET routes:** none writes.
- **Redirects:** `back=` redirects go only to fixed paths.
- **SQL:** the f-string `UPDATE applications SET {column}` (`approvals.py:274`) takes `column` only from the fixed `DOC_POINTERS` table. Every other f-string SQL in the diff interpolates code-controlled names or generated placeholders.
- **Templates:** autoescape is forced on, there is no `|safe` or `Markup`, and values inside scripts go through `tojson`.
- **`/import`:** the temp folder is removed on every outcome tried (success, model error, read error, refusal, crash).
- **pypdf:** size is checked before parsing; encryption and page count are checked before text extraction.
- **Model calls:** no write transaction is held during a model call (drafting, answers, prep, intake). Discovery commits before every fetch.
- **Threads:** no connection is shared across threads.
- **Turbo:**
  - Pass, unpass and enqueue are safe to repeat.
  - The worker claims an item atomically.
  - Restart puts running items back in the queue.
  - A closed tab sends the pending swipe with `sendBeacon`.
- **Backups:**
  - `prune` touches only its own folder names; a junction named like a copy wasn't followed.
  - `.env` is never copied.
  - A manifest with `../` can't redirect a restore.
- **Migrations:** every column added in this range is nullable with no default.
- **Timestamps:** every stamp in the range uses one format, so text comparisons are sound. Turbo's "today" is the local date.
- **Learning:**
  - Each feature is capped at ±0.05 and the total at ±0.10.
  - The 30-swipe and 5-observation minimums are applied.
  - Each posting group counts once, and reset works.
  - Ranking never filters or writes.
- **Find:**
  - Guesses make at most 9 requests.
  - A guessed board never says "same job".
  - The Greenhouse name check runs before jobs are read.
- **UI:** none of the new pages scrolls sideways at 375 px, and both themes read correctly.
